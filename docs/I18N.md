# Localization

Only Paraglide JS and the inlang project are used. The message source of truth is messages/{locale}.json.

Selected national/official language coverage: en English; id Indonesian; ms Malay (Malaysia, Brunei, Singapore); fil Filipino; th Thai; vi Vietnamese; my Burmese; km Khmer; lo Lao; zh-SG Chinese (Singapore); ta Tamil (Singapore); tet Tetum (Timor-Leste); pt-TL Portuguese (Timor-Leste). This does not claim support for every regional language in Southeast Asia.

Update English and all other message files for every new user-facing string. Run npm run check:locales. The checker validates key and placeholder completeness across all 13 catalogs. A flagged language dialog replaces the native select; mobile quick settings groups language, share and theme. Independent human review remains outstanding, especially safety, install and bot-verification wording; key completeness is not translation quality.

The URL determines the locale. Language selection navigates in place while retaining query and hash. Build-time SSR uses Paraglide's request-scoped middleware; all 13 locale homepages and legal routes are prerendered with localized body content, canonical URLs, hreflang links and Open Graph locale/alternate metadata. A shared fallback remains for offline recovery and unknown client routes.
